lib/ops-proxy.js (NEW; all functions are no-ops / return false in sheets mode except mapSheetsAction):
- mapSheetsAction(action) -> 'delete_ferm_schedule' when action === 'archive_ferm_schedule' and mode is sheets, else action
- intercept(action, payload, req, res, logTag, forward) -> Boolean, returned synchronously (true = this module owns the response). forward() is a
  zero-argument callback supplied by pos.js that runs forwardToAppsScript for this request. Handles in PG modes:
    get_vessels, get_ferm_schedules -> store envelope; create_/update_/delete_/archive_/propagate_ferm_schedule -> store;
    create_batch with payload.schedule_id -> returns true, then getStepsJson; not_found -> res.json(envelope); ok -> sets payload.schedule_steps_json and calls forward()
  Status mapping: stale_schedule -> 409 {ok:false, error, code:'stale_schedule', message}; schedule_in_use -> 409 {.., code:'schedule_in_use', recipe_refs, batch_refs};
  other business {ok:false} -> 200 as Apps Script does; store rejection -> log.error + 502 {ok:false, error:'server_error'} (code batch_ref_unavailable -> same 502).
  actor = req.staffEmail || 'middleware'; expectedUpdatedAt = payload.expected_updated_at.
- decorateForward(payload, isRead) -> in PG modes for writes: payload.collect_vessel_status = true; if payload.server_token, payload.vessel_sheet_write = sheetMirror.isMirrorEnabled()
- afterUpstream(data, payload) -> Promise: in PG modes, if Array.isArray(data.vessel_status_changes): apply via vesselStore.applyStatusChanges(changes, {actor: payload.acting_user || 'middleware'}) (failure -> Sentry/log.error with vessel ids only, never rejects); always delete data.vessel_status_changes. For action get_batch_init: replace data.data.schedules with fermScheduleStore.list() schedules (failure -> 502 path by rejecting).
</interfaces>
