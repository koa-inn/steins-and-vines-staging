<interfaces>
Same module contract as lib/recipe-pg.js (client from db.withTransaction, $n only, business rejection
resolves {ok:false,...}, infra errors propagate, underscore keys stripped by the facade).

Schedule object (sheet key order): schedule_id, name, description, category, steps (JSON.stringify of the
array), is_active (boolean), created_at (ISO), created_by, last_updated (ISO ms of updated_at), steps_parsed (array).

Signatures (consumed by 86-11 ops-mirror, 86-13 ferm-schedule-store):
- listSchedules(client, {includeArchived}) -> Array (order: length(schedule_id), schedule_id)
- getSchedule(client, id) -> object|null (archived included)
- createSchedule(client, payload, {actor, now}) -> {ok:true, schedule_id, _scheduleId} | {ok:false, error:'missing_fields'|'invalid_steps'|'too_few_steps'|'no_packaging_step', message}
  (match the success envelope keys of adminApi.gs createFermSchedule; read it to confirm)
- updateSchedule(client, id, payload, {actor, now, expectedUpdatedAt}) -> {ok:true, message, _scheduleId} | {ok:false, error:'not_found'|'stale_schedule'|steps errors, message}
- archiveSchedule(client, id, {actor, now, expectedUpdatedAt}) -> {ok:true, message, _scheduleId} | not_found | stale_schedule
- deleteSchedule(client, id, {expectedUpdatedAt, recipeRefCount, batchRefCount}) -> {ok:true, message, _scheduleId, _deleted:true} | {ok:false, error:'schedule_in_use', message, recipe_refs, batch_refs} | not_found | stale_schedule
  Throws Error('recipeRefCount and batchRefCount required') unless both are non-negative integers (recipe-pg deleteRecipe idiom).
- countRecipeReferences(client, id) -> integer (select count(*) from recipes where schedule_id = $1) — used by the store only when RECIPES_STORE is not sheets.
STALE message: 'This schedule was changed since you opened it — reload to see the latest'
IN-USE message: 'This schedule is used by N recipe(s) and M batch(es). Archive it instead.'
</interfaces>
