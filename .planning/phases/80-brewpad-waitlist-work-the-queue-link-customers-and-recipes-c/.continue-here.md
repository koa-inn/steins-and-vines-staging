## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting a first-request probe | `/api/bookings/services` returned a perfect payload on the FIRST curl and double-encoded garbage on every subsequent call, because only the cache-hit path was broken. A single probe "confirmed" the endpoint was wired and it was not. | advisory | Probe cached endpoints **at least twice**. A single call only ever exercises the miss path. |
| Fixing alignment without checking the page's idiom | A `.content` alignment mismatch on beer.html was "fixed" by left-aligning paragraphs site-wide. Locally correct, globally wrong — centred is this site's idiom. Owner pushed back and it was reverted. | advisory | Before changing a shared style rule, look at 2–3 sibling pages and match the dominant pattern rather than optimising the section in isolation. |
| Tests that mock the seam they're meant to guard | `bookings.test.js` had a test literally named "returns cached data without double-parsing" that mocked `cache.get` with an already-parsed object. It could never fail on the real bug, which lived between `cache.set` and `cache.get`. | advisory | When testing a cache/serialisation boundary, round-trip through the real set/get semantics rather than mocking the parsed result. |
