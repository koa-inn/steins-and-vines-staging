**D-24 has no home in the locked transport, so this plan gives it one.** CONTEXT.md `<code_context>`
locks the manual-add ROW WRITE to the admin proxy (`add_waitlist_entry`), and RESEARCH.md/PATTERNS.md/
UI-SPEC.md all build on that. But the admin proxy is a generic single-call passthrough straight to
Apps Script — it cannot run the MailerLite leg that D-24 requires, and `MAILERLITE_API_KEY` is
server-only so BrewPad cannot run it either. RESEARCH.md never addresses this (a genuine research
gap, flagged here rather than silently dropped).

Resolution: keep the locked admin-proxy path for the row write, and add ONE thin staff-tier endpoint
`POST /api/waitlist/:id/mailerlite-sync` whose entire job is the fire-and-forget subscribe plus the
`mailerlite_synced` flag write, lifted verbatim from the public route's block at
`zoho-middleware/server.js:262-276`. BrewPad calls it after a genuinely-new manual add (plan 80-05).
This keeps `POST /api/waitlist`'s public path — and therefore Phase 78 D-06 — completely untouched.

**D-23 needs no Apps Script response change.** `addWaitlistEntry` keeps its identical `{ok, id}`
return on both branches (plan 80-01 Task 2). The staff disclosure is derived client-side in plan
80-05 by comparing the returned `id` against a `get_waitlist` snapshot taken immediately before the
write. Structurally, there is nothing new for the public path to leak.

**The booking link is resolved client-side.** `GET /api/bookings/services`
(`zoho-middleware/routes/bookings.js:133-175`) already calls `calcom.listEventType` and 24h-caches a
real `bookingUrl` per service, and is already public. BrewPad reads it to build the D-05 preview and
passes the resolved URL to the send endpoint. Do NOT add a second Cal.com call, and do NOT copy
`sendBottlingInvite`'s hardcoded `CALCOM_BOTTLING_BOOKING_URL` construction — D-06 mandates the
`listEventType` path (RESEARCH Pitfall 3).

| Boundary | Description |
|----------|-------------|
| BrewPad browser -> middleware | Session-tier staff credential (`x-session-token`/`sv_session`); carries a staff-edited email subject/body and a customer email address |

| middleware -> Apps Script | Server-only `APPS_SCRIPT_SERVER_TOKEN`; writes the durable row |
| admin proxy -> Apps Script | Generic action passthrough, gated by two deliberately separate allow-lists |
