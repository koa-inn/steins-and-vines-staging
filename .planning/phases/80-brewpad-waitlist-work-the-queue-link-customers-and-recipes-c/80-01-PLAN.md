Resolutions for the `### Claude's Discretion` items this plan owns. Implement exactly; do not
re-litigate.

- **`recipe_ids` format: pipe-delimited (`|`), no spaces.** Recipe ids come from
  `generateNextId(RECIPES_SHEET_NAME, 'SV-R-', 6)` (`adminApi.gs:3629`) and look like
  `SV-R-000003` — a pipe cannot occur inside one.
- **`position` scheme: a positive integer meaning "this row's target 1-based rank in the merged
  queue", stored ONLY on the pinned row.** Pinning writes exactly one cell on exactly one row, so
  no unrelated row's `signed_up_at` is ever rewritten. The merge happens at render time in
  `js/brewpad.js` (plan 80-03); this layer only stores and validates.
- **`customer_name` opportunistic refresh: NOT implemented** anywhere in this phase (D-03 already
  accepts staleness; the discretion note marks refresh "nice-to-have").
- **WR-02 (optimistic locking): CARRIED FORWARD, not folded in.** The `updateReservation`-style fix
  needs a `last_updated` column — a seventh new column D-17 does not list and D-20's "one
  migration" framing forbids adding silently. Recorded as a code comment (Task 3), which is the
  remediation `78-REVIEW.md` itself proposes for an accepted finding.
- **IN-01 (status not routed through `waitlistCellSafe`): FOLDED IN.** One line, zero behaviour
  change today, and this plan already rewrites the surrounding block.
