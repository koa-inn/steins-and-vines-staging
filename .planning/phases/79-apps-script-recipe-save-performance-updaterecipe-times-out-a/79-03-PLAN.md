<objective>
Rewrite `updateRecipe` (`apps-script/adminApi.gs:3583-3681`) so a 13-ingredient recipe save costs
roughly **6 Sheets API calls instead of ~54** — implementing all five ordered fixes (D-04 through
D-08) plus ingredient-id stability (D-09) and the local lock retune (D-10) in a single pass, so the
owner pays for exactly **one** manual Apps Script redeploy.

Purpose: `PUT /api/recipes/:id` currently 502s on every save, including a pure rename, because
`updateRecipe` does ~14 individual `setValue` calls on the recipe row, then deletes 13 ingredient
rows one at a time, then calls `generateNextId` (a full column scan) 13 times inside the insert
loop, then `appendRow`s 13 times. At Apps Script's 100-500 ms per Sheets operation that is 5-25 s
against a 15,000 ms client ceiling. Round-trip **count** is the cause, not data volume — the same
save would be equally slow on an empty sheet (D-01).

Output: One rewritten function in one file. **This edit is inert until the owner redeploys** —
79-04 does that and live-probes it.

Honest statement of test coverage: **the Sheets round-trip reduction has no automated test and
cannot have one.** There is no `SpreadsheetApp` outside Google's runtime, and
`zoho-middleware/__tests__/recipes.test.js` mocks `axios.post` outright, so it stands in for the
entire Apps Script round-trip and is blind to this change by construction. Do NOT add a test there
that pretends otherwise — STATE.md records a commit that passed its suite for four days while dead
in production for exactly this reason. What IS locally verifiable is (a) that the pure helpers this
function calls behave correctly, and (b) that `adminApi.gs` still parses — both covered by 79-02's
suite, which runs as part of `npm test`. Everything else rests on 79-04's live probe.
</objective>
