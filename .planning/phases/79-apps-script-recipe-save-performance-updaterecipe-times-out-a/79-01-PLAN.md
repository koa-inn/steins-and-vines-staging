zoho-middleware/routes/recipes.js:668-671 — the ONLY producer of this line:
  `log.error('[api/recipes] PUT ' + req.params.id + ' failed: ' + err.message);`
  `res.status(502).json({ error: 'Unable to update recipe', code: 'save_failed' });`

zoho-middleware/routes/recipes.js:25-42 — `callAppsScriptPost(action, payload)` uses
`axios.post(url, body, { headers, timeout: 15000, maxRedirects: 5 })`. On a client-side timeout
axios rejects with `err.code === 'ECONNABORTED'` and
`err.message === 'timeout of 15000ms exceeded'` — that exact string is the CONFIRMING signal.

Non-timeout messages that would CONTRADICT the diagnosis (non-exhaustive):
- `Apps Script not configured` (env vars missing — thrown at recipes.js:29-31)
- `Request failed with status code 401` / `403` / `302` (auth or redirect problem, not slowness)
- Any `getaddrinfo` / `ECONNRESET` / `socket hang up` (network, not slowness)
- A JSON-parse or `Cannot read property` message (a real bug in the response handling)

Note the 422 path is NOT this line: a `{ok:false}` Apps Script response returns 422 with
`data.message`, never reaching the catch. So a 502 + this line means the promise REJECTED.
</interfaces>
