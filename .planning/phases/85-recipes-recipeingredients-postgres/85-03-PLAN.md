Contract added by this plan (consumed by 85-06 recipe-store.js):

updateRecipe(client, payload, {expectedUpdatedAt, now}) -> Promise<
    {ok:true, _recipeId, _ingredientsRewritten: Boolean}
  | {ok:false, error:'missing_id'|'not_found'|'stale_recipe'|'invalid_data', message}>
  - payload.recipe_id required; only fields !== undefined are touched:
    strings (sanitizeInput): name, style, description, status, notes, schedule_id
    numerics (Number, must be finite): locked_price, service_fee, materials_fee, batch_size_l, abv, ibu, colour_srm
    pricing_mode via normalizePricingMode only when provided
    updated_at ALWAYS set to opts.now (JS Date, ms precision — never SQL now())
    ingredient_count and expected_updated_at in the payload are ignored (not columns)
  - ingredients only when payload.ingredients !== undefined (JSON string parsed; invalid -> invalid_data)
deleteRecipe(client, recipeId, {expectedUpdatedAt, batchRefCount, now}) -> Promise<
    {ok:true, deactivated:true, message:'Recipe deactivated (has batch references)'}
  | {ok:true, deleted:true, message:'Recipe deleted'}
  | {ok:false, error:'missing_id'|'not_found'|'stale_recipe', message}>
  (each ok result also carries _recipeId for the facade)
D-03 compare: stale when expectedUpdatedAt is missing/empty/unparseable OR
  new Date(expectedUpdatedAt).getTime() !== lockedRow.updated_at.getTime()
D-03 message: 'This recipe was changed since you opened it — reload to see the latest'

From 85-01 recipe-rules: normalizeRecipeIngredientTuple(itemId, qty, unit), recipeIngredientsUnchanged(incoming, stored), planIngredientIds(incoming, storedIds)
