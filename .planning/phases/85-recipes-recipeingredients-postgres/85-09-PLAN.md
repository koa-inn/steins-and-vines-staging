<objective>
Ship the browser half of D-03 in every recipe write caller (admin editor, admin kiosk quick-edit, BrewPad): send the optimistic-concurrency token, and
surface the server's 409 `stale_recipe` rejection with a clear message and a Reload action.

Purpose: D-03 requires the admin editor to surface the message and offer a reload; BrewPad uses the
same endpoints so it must too. Orchestrator decision (Open Question 2, owner may override): the
server REJECTS a missing token in dual/postgres, so this plan must reach staging in the same deploy
as, or before, any RECIPES_STORE change off `sheets` (enforced in 85-12). In `sheets` mode the token
is ignored server-side (D-04 last-save-wins unchanged).
The kiosk quick-edit (admin.js kioskSaveRecipeQuickEdit) is included because it PUTs /api/recipes/:id
too: without the token it would 409 permanently in dual/postgres, and because PUT returns only
{ok:true} it must refresh its local updated_at after each save or a second edit would self-409.
Output: edited editors + quick-edit, two new jsdom suites, rebuilt min artifacts.
</objective>
