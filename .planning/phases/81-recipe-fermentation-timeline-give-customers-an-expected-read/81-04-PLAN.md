<objective>
Give the recipe editor a fermentation-schedule picker that actually has options in it, round-trips
the value, and warns without blocking when an active recipe has none.

Purpose: this is the surface the owner uses to execute D-10's backfill — attaching schedules to
the three active recipes is the phase's release gate, and it happens here. D-11 makes the warning
advisory only: no new way for a save to fail on a form staff use under time pressure, and D-09
keeps the public page correct either way.

Output: a fifth field in the existing recipe form grid, its load/save wiring, a live
warn-don't-block message, one CSS modifier line, and the fix for the lazy-load gap that would
otherwise render the picker empty.
</objective>

beer-category entries FIRST and every other entry after them. Apply `escapeHTML` to
`schedule_id`, `name` and `category`, copying the stricter `#sa-schedule-select` loop at

(`js/admin.js:7602-7606`) offers an explicit "None" category option, and a beer recipe may
legitimately reuse a generic or blank-category template. Hiding non-beer entries would yield an
empty dropdown for real recipes. Sort, do not filter.

In `populateRecipeForm` (`js/admin.js:8771`), immediately after the existing `recipe-colour`
assignment, set the picker's `innerHTML` to `buildScheduleOptionsHtml(r.schedule_id || '')`.
Rebuilding the options here rather than once at page load is deliberate: `loadBatchInit` is
asynchronous and may not have resolved when the tab first renders. Guard the lookup with
`if (scheduleSelect)` in the same defensive style as the existing `pricingModeSelect` handling a
few lines below, so a missing element never throws.

In `saveRecipe`'s `formData` object literal (`js/admin.js:9074-9093`), add
`schedule_id: document.getElementById('recipe-schedule-select').value || null,` immediately
after the existing `colour_srm` entry. `null` is correct and intentional for the cleared case:
Apps Script's `sanitizeInput` collapses `null` to `''` (`apps-script/adminApi.gs:3450`), so
clearing the picker writes an empty cell rather than the string "null". Do not send `undefined`
— `updateRecipe`'s `stringFields` loop is gated on `payload[field] !== undefined`, so an
undefined value would silently skip the write and make clearing a schedule impossible.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apps Script response → admin DOM | Template `name`, `category` and `schedule_id` come from a staff-editable sheet and are interpolated into `<option>` markup |
| staff form → Apps Script `update_recipe` | The chosen `schedule_id` crosses into a sheet cell |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-81-17 | Tampering | `buildScheduleOptionsHtml` string-concatenated `<option>` markup | mitigate | `escapeHTML` is applied to `schedule_id`, `name` and `category`, copying the stricter `#sa-schedule-select` loop (`js/admin.js:7346-7352`) rather than the unescaped `#batch-schedule-select` loop. Template names are staff-authored and land in a sheet cell, so they are not fully trusted input |
| T-81-18 | Tampering | `#recipe-schedule-warning` message text | mitigate | Set via `textContent`, never `innerHTML`. The string is a constant with no interpolated data, so there is no injection surface at all |
| T-81-19 | Tampering | `schedule_id` submitted by `saveRecipe` | mitigate | Server-side, `updateRecipe`'s `stringFields` loop applies `sanitizeInput` and the batched write carries the existing formula-safety per-cell fallback (plan 81-01, T-81-01). The client-side value is a select value, not free text, so the reachable value set is the option list |
| T-81-20 | Denial of service | Availability of the recipe save path | mitigate | D-11 is advisory only. `canActivateRecipe` is explicitly not modified, and an acceptance criterion greps its body for `schedule` and requires zero hits — so this phase cannot introduce a new way for a staff save to fail |
| T-81-21 | Information disclosure | Schedule template detail in the admin DOM | accept | `admin.html` is a staff-only surface behind the Google-session tier established in Phase 46. Template names and categories are staff data and are already rendered in two existing dropdowns on the Batches tab; this adds no new exposure class |
| T-81-SC | Tampering | npm/pip/cargo installs | accept | No package is installed. RESEARCH.md § "Package Legitimacy Audit" records the phase as installing zero new dependencies |
