## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → middleware `GET /api/recipes[/:id]` | The public boundary. A NEW field (`ferment_days`) crosses it for the first time this phase |
| middleware → Apps Script `doGet` | A NEW outbound call path carrying `APPS_SCRIPT_SERVER_TOKEN` for `get_ferm_schedules` |
| Redis → middleware | A NEW cache key (`sv:ferm-schedules`) holding internal schedule data including step titles and transfer flags |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-81-06 | Information disclosure | `toPublicRecipe` projection | mitigate | `PUBLIC_RECIPE_FIELDS` gains exactly one entry, `ferment_days`. `schedule_id`, `name` (of a template), `steps`, `steps_parsed`, `title` and `is_transfer` are never added. Enforced by a new negative assertion in `recipes-public-guard.test.js` that greps the serialized anonymous response for those substrings, so a future careless addition fails CI rather than shipping |
| T-81-07 | Information disclosure | `sv:ferm-schedules` Redis value | mitigate | The cache holds the full internal schedule objects, but the only code that reads it is `enrichFermentDays`, which reduces each schedule to a single integer via `maxNonPackagingOffset` before anything reaches a response. No route serves the cached value directly, and none is added |
| T-81-08 | Information disclosure | `APPS_SCRIPT_SERVER_TOKEN` on a new call path | mitigate | The token travels as an HTTPS query parameter to the same Apps Script origin already used by `pos.js:3323` — no new secret, no new destination, no new storage. It must never be logged: the `.catch` handler logs `err.message` only and must not log the axios `config` object or the request URL, both of which would embed the token |
| T-81-09 | Tampering | Cache poisoning / stale derivation | accept | A poisoned or stale `sv:ferm-schedules` entry can only change a displayed week count, not authorize anything. Worst-case combined staleness is Apps Script `'gfs'` 300s plus middleware 300s; plan 81-01's `'gfs'` eviction shortens the first leg. The D-15 copy shipped in plan 81-06 says "will change what customers are told" and deliberately does not promise immediacy |
| T-81-10 | Denial of service | Schedules fetch failure blocking the recipe list | mitigate | `fetchFermSchedules` resolves to `[]` on axios rejection, on `ok:false`, and on missing env vars; `enrichFermentDays` carries its own `.catch(function () {})`. A schedules outage degrades to "no Ready in column" (D-09), never to a 502 on the public beer page. Covered by an explicit test case |
| T-81-11 | Elevation of privilege | Anonymous caller forcing a staff payload | accept | Unchanged surface. `isRecipeStaff` already discards an anonymous caller's `?status=` (T-74-03) and re-filters to `active` server-side (T-74-01) before projection. This plan adds no new branch to that logic |
| T-81-SC | Tampering | npm/pip/cargo installs | accept | No package is installed. RESEARCH.md § "Package Legitimacy Audit" records the phase as installing zero new dependencies |
