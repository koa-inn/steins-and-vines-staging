<objective>
Tell staff what a template edit will change before they make it, and make the recipe→schedule
link do real internal work by defaulting the batch-activation dropdown to the recipe's own
template.

Purpose: D-15 exists because live batches are already safe — they hold a frozen
`schedule_snapshot` taken at activation (`apps-script/adminApi.gs:2232`) — but public marketing
copy is not. Once this phase ships, a day-offset edit changes what a customer is told on
`beer.html`. D-04 makes the link more than decorative: the schedule a recipe is linked to becomes
the default at the moment a batch is actually scheduled.

Output: a usage-count helper, an informational banner in the template editor, and a one-line
default on the activation dropdown — plus a documented finding on the one leg of D-04 the current
code cannot support.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apps Script recipe/batch data → admin modal markup | `recipe_id`, `schedule_id` and a usage count are read from sheet-sourced objects and rendered into staff-facing modals |
| admin browser → middleware `GET /api/recipes/:id` | An existing staff-authenticated read, reused on a new call site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-81-28 | Tampering | D-15 note interpolation | mitigate | Only an integer count is interpolated into the banner string; the template's name and description are deliberately NOT interpolated, so there is no sheet-sourced text in this markup at all |
| T-81-29 | Tampering | `#sa-schedule-select` pre-selected value | mitigate | The value is assigned to an existing `<select>`'s `.value` property, not concatenated into markup. An unmatched value simply leaves the select on its empty option. Options themselves are already `escapeHTML`-treated by the existing loop at `js/admin.js:7348-7351` |
| T-81-30 | Denial of service | Batch activation blocked by a failed pre-selection lookup | mitigate | The single-recipe fetch is non-fatal with an explicit `.catch`; a failure yields no default and the modal opens normally. An acceptance criterion requires that `.catch`. Activation is a time-pressured staff action and must never depend on an optional convenience |
| T-81-31 | Repudiation | Staff misled about a template edit's reach | mitigate | The count is derived from `_recipesState.list`, which honours the current status filter and is therefore a lower bound. A code comment records that, and the copy states consequence rather than an exact guarantee, so the note cannot be read as a complete audit |
| T-81-32 | Elevation of privilege | New read path from the admin UI | accept | `GET /api/recipes/:id` is an existing staff-authenticated endpoint already called from two other places in `js/admin.js`; this adds a call site, not a capability. No new endpoint and no new auth path |
| T-81-33 | Denial of service | Template save blocked by the new note | mitigate | The `#sched-submit` validation handler is not modified, and an acceptance criterion diffs its body to prove it. D-15 is informational by design |
| T-81-SC | Tampering | npm/pip/cargo installs | accept | No package is installed. RESEARCH.md § "Package Legitimacy Audit" records the phase as installing zero new dependencies |
</threat_model>
