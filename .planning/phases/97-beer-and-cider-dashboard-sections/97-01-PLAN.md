<objective>
Give beer and cider recipes two optional fields, Target OG and Target FG (degrees Plato), stored in the Postgres
`recipes` table, validated on every write path and carried by the prod-only Apps Script mirror (D-06).

Purpose: the beer/cider card (D-07) and the Phase 96 G8 expected curve read `og` / `target_fg` from `recipe_snapshot`,
but no recipe holds them today. This plan makes the recipe store hold them; plans 97-02 and 97-05 copy them into snapshots.
Output: migration 0009, rule + store + route changes, Apps Script lazy column ensure, tests.

Discretion choices (CONTEXT "Claude's Discretion" — field names and carrying):
- Column/key names `target_og` and `target_fg` (numeric, nullable, no CHECK: the allowlist forbids DROP CONSTRAINT, precedent 0006).
- Range 2..40 °P, the same range `snapshotPlato` in lib/batch-pg-read.js already accepts, and target_fg must be below target_og when both are set.
- Apps Script: columns are added lazily (only when a mirrored recipe has a value) so existing mirror/header tests stay untouched (CLAUDE.md rule 10) and legacy sheets stay identical until the first value exists.
- No backfill of the two existing beer batches (D-06: no backfill writes without dry run + owner OK; out of scope).
</objective>
