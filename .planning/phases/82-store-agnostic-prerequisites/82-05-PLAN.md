<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anyone with a batch QR URL → /api/batch/public/* | Fully unauthenticated at the middleware; the batch token is the only credential |
| Middleware → Apps Script (token path) | Middleware forwards the token; Apps Script validates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-05-01 | Elevation of Privilege | client choosing the Apps Script action | mitigate | Action fixed per route; payload built from a field whitelist; client `action` ignored (tests assert) |
| T-82-05-02 | Elevation of Privilege | client smuggling server_token to reach the privileged doPost branch | mitigate | server_token never included (explicit payload); doPost's batch_token branch is checked before server_token anyway |
| T-82-05-03 | Denial of Service / brute force | token guessing and scraping on unauthenticated routes | mitigate | batchPublicLimiter 30/min per IP, no Redis-down skip (D-14); 128-bit tokens validated by Apps Script |
| T-82-05-04 | Spoofing | missing middleware-side token check | accept | D-13: Apps Script remains the validator this phase; middleware validation deferred to Phase 87 |
| T-82-05-05 | Elevation of Privilege | guard exemption too broad | mitigate | Prefix is exactly '/batch/public/'; tests prove /api/admin/proxy and other /api/batch POSTs still require credentials |
| T-82-05-06 | Tampering | a batch-A token updating a task_id that belongs to batch B | accept (pre-existing, flag) | handleBatchTokenPost does not check the task belongs to payload.batch_id — pre-existing Apps Script gap, unchanged by this phase; recorded in SUMMARY as a follow-up for Phase 87 |
| T-82-05-07 | Information Disclosure | token in the GET query string appearing in Railway request logs | accept | Same exposure as today's Apps Script GET URL; server.js logs req.path (no query string) |
</threat_model>
