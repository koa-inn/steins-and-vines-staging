## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness browser → middleware | Local dev resolves MIDDLEWARE_URL to PRODUCTION; an unmocked call would hit the live service with a fake session |
| staging → capture file | Real customer data crosses into the developer machine during capture |
| repo → public Pages site | Anything committed under tests/ is publicly served on production |
| shipped JS → harness | A test flag in js/ could enable an auth bypass in production |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-99-01 | Information disclosure | tests/perf/fixture/dashboard-fixture.json | mitigate | allowlist-first anonymizeFixture (unknown string keys redacted) + key rules (emails, phones, customer names, tokens, free text) + Jest PII/token grep over the committed fixture; raw capture lives only in gitignored tests/perf/.raw/; manual `git diff --cached` review before commit (tests/ is public on production) |
| T-99-02 | Elevation of privilege | auth bypass for the harness | mitigate | No seam in js/ or the repo's brewpad.html; seed.js and gsi-stub.js are injected at serve time by server.mjs only; acceptance grep for the seam markers `__harness`, `bp_perf`, `tests/perf` over js/ css/ brewpad.html is empty |
| T-99-03 | Tampering | harness reaching the production middleware | mitigate | sheets-config.js rewritten to local origin at serve time + seed.js fetch wrapper rejecting *.up.railway.app and googleapis hosts + server log check of zero forwarded requests |
