SHEET: tab name `Waitlist`, in the same spreadsheet as `Batches`/`GiftCards`.
HEADER ROW (row 1, this exact order, lowercase):
  id | email | category | status | signed_up_at | mailerlite_synced | notes

  id                : column A. Utilities.getUuid() string. NEVER the email — keeps findRowById's
                      "column A is the unique key" assumption true even once D-02's multi-category
                      future lands and the same email appears twice.
  email             : normalized lowercase-trimmed customer email.
  category          : 'beer' at launch. Free string (D-02).
  status            : exactly one of 'waiting' | 'contacted' | 'booked' | 'removed' (D-05).
  signed_up_at      : ISO-8601 UTC string from new Date().toISOString().
  mailerlite_synced : boolean true/false (D-07).
  notes             : free text, may be empty (D-08).

APPS SCRIPT ACTIONS:

1. add_waitlist_entry  — POST, routed ONLY inside doPost's existing validated `server_token` block.
                          Deliberately absent from both admin-proxy whitelists (staff never add rows).
   request  : { action:'add_waitlist_entry', server_token, email, category }
   response : { ok:true, id:'<uuid of the row this email+category now occupies>' }
              IDENTICAL SHAPE for a brand-new row and a dedupe hit. No `created`, `existing`,
              `duplicate` or `already_listed` field may ever appear (D-06 non-disclosure).
   failures : { ok:false, error:'invalid_email' }
              { ok:false, error:'waitlist_unavailable', missing:[...] }  (tab absent/headers drifted)

2. get_waitlist        — READ, routed in handleReadAction. Goes in BOTH admin-proxy whitelists.
   request  : { action:'get_waitlist' }   (proxy injects server_token)
   response : { ok:true, data:[ { id, email, category, status, signed_up_at,
                                  mailerlite_synced, notes }, ... ] }
              `_row` is NEVER included.

3. update_waitlist_status — POST, routed in doPost's `server_token` block.
                            Goes in ADMIN_PROXY_ACTIONS only, NOT ADMIN_PROXY_READS.
   request  : { action:'update_waitlist_status', server_token, id,
                status?, notes?, mailerlite_synced? }   (at least one of the three required)
   response : { ok:true, id, status:'<row status after the write>' }
   failures : { ok:false, error:'not_found' }
              { ok:false, error:'invalid_status' }
              { ok:false, error:'no_fields' }
              { ok:false, error:'waitlist_unavailable', missing:[...] }

MIDDLEWARE `/api/waitlist` RESPONSE CONTRACT (unchanged, do not alter in any plan):
  200 { success:true } | 400/503/500 { error:'<message>' }
